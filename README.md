# Career Quest · HackAlem AI / Halyk Bank

Карьерный навигатор: профиль → разрывы до следующего грейда → объяснимый следующий шаг → завершение → обновлённый прогресс. HR видит частые разрывы, сотрудников без шага и участие по событиям.

**Основной сценарий работает на стартовом ките** из `case/case_1/career_quest_dataset`: 200 сотрудников, 40 событий, 60 навыков, 2 743 записи истории. Дата среза — 2026-10-01. Временные демопрофили не используются при обычном запуске. Дополнительный синтетический профиль проверен в фактическом формате кита; скрытых профилей жюри у нас нет.

## Установка и запуск

Python 3.11+ (интеграция проверена на Python 3.11.9 / Windows). Из корня проекта:

```bash
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

Одна команда запуска:

```bash
python -m streamlit run app.py
```

Открыть http://localhost:8501. Без ключей приложение использует детерминированное ранжирование core и честно показывает «API выключен». Папка данных задаётся через `CAREER_QUEST_DATA_DIR` до запуска. Если активация PowerShell запрещена, используйте `.\.venv\Scripts\python.exe` вместо `python`.

Обычный запуск требует настоящий `core/api.py`. При его отсутствии появляется понятная ошибка; автоматического перехода на временные рекомендации нет. Временный адаптер используется только явно в UI-тестах.

Светлая тема виджетов задаётся в `.streamlit/config.toml`. Цвет текста на светлых карточках и в меню задан явно, чтобы системная или сохранённая тёмная тема браузера не делала его белым на белом фоне.

## Архитектура и AI

`Streamlit → ui/core_adapter.py → core/api.py → core/engine.py → core/ai.py (опционально)`.

`app.py` управляет экранами и состоянием сессии, `ui/components.py` и `styles/main.css` — представлением. Адаптер приводит фактические поля core (`name`, `label`, `progress_percent`, `activity_participation`) к формату UI. Он не выбирает активности, не меняет их порядок и не вызывает модель. `ui/adapter.py` — совместимый фасад того же адаптера для переданных первой моделью тестов.

Перед импортом и завершением создаётся копия датасета. Сессия обновляется только после успешного ответа; `complete_activity()` сопровождается новым `get_employee_view()`. Просмотры кешируются внутри сессии и сбрасываются при изменении данных. Имена навыков и отметки критичных требований берутся из каталога.

Детерминированный слой считает требования и разрывы следующего грейда текущей роли, воспроизводит завершения после last_review_date по gain/max_level, фильтрует обязательные/неподходящие/недоступные события и проверяет prerequisites. Ранжирование учитывает критичные навыки, историю пропусков и отказов, начатые активности, формат работы и трудозатраты. Формула в CORE_NOTES.md.

LLM выбирает один шаг из максимум трёх близких лидеров (разница ≤ max(1 балл, 10% оценки лидера)) и упорядочивает существующие фактические объяснения. Модель не генерирует новые факты и не меняет score, требования, навыки, gain/max_level или прогресс. Ответ с неизвестным событием или индексом причины отклоняется. Интерфейс показывает AI/fallback.

В текущем core нет свободного текста AI: персональное объяснение в карточке — дословная приоритетная причина из ответа движка. Полный список факторов и ожидаемый прирост показаны отдельными блоками. Статус поясняет, применялся ли AI при выборе и упорядочивании причин. При таймауте UI показывает подтверждённые детерминированные причины core. Адаптер также поддерживает отдельный `ai_explanation`, если движок начнёт возвращать его позднее; сейчас такой текст не выдумывается.

Реализованы OpenAI Responses со Structured Outputs и NVIDIA NIM Chat Completions. **Живой вызов API не проверен: в рабочем окружении нет ключей.** Успех, ошибки, таймаут и некорректные ответы проверены через mock. Документация: [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [NVIDIA](https://docs.api.nvidia.com/nim/re/reference/llm-apis).

### Переменные окружения

| Переменная | Значение |
|---|---|
| CAREER_QUEST_AI_PROVIDER | none (по умолчанию), openai, nvidia |
| CAREER_QUEST_AI_MODEL | ID модели, доступной вашей команде; обязательно для API |
| OPENAI_API_KEY | Секрет OpenAI, только в окружении |
| NVIDIA_API_KEY | Секрет NVIDIA, только в окружении |
| CAREER_QUEST_AI_TIMEOUT | 8 секунд по умолчанию, ограничение 0.1–9 секунд |

Задайте переменные до запуска. Не помещайте ключи в код или Git. `.env` автоматически не загружается. Жёсткое ограничение ожидания выполняется фоновым потоком; повторов нет. После ошибки одинаковые факты 30 секунд используют fallback. До 128 успешных ответов кешируются, одновременно допускаются два HTTP-запроса. HR не вызывает API для каждого профиля. Имя, employee_id и исходная история в API не отправляются; передаются роль/грейд/цель/формат работы и факты кандидатов.

Пример [`.env.example`](.env.example), без секретов:

```dotenv
CAREER_QUEST_AI_PROVIDER=none
CAREER_QUEST_AI_MODEL=
CAREER_QUEST_AI_TIMEOUT=8
OPENAI_API_KEY=
NVIDIA_API_KEY=
CAREER_QUEST_DATA_DIR=case/case_1/career_quest_dataset
```

Для реального API задайте `openai` или `nvidia`, доступный команде ID модели и соответствующий ключ в окружении процесса. UI не хранит ключи, не предлагает поля их ввода и не отправляет собственных запросов провайдеру.

## Входные данные

Схема прочитана в README.ru.md стартового кита:

- employees.json: объект с массивом employees; meta необязателен для дополнительного файла. Профиль: employee_id, full_name, department, role, grade, manager_id, hire_date, tenure_months, work_format, preferred_language, career_goal, skills, last_review_date. skills — skill_id → целое 0–5, отсутствующий навык считается 0.
- skills.json: meta.as_of_date, skills[], role_profiles[] с required_skills и critical_skills.
- events.json: events[], включая develops_skills (skill_id/gain/max_level), prerequisites, mandatory, аудиторию и upcoming_sessions.
- activity_history.csv: `record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by`.

Статусы: completed, in_progress, dropped, no_show, declined, overdue. UTF-8, до 10 МБ на файл. Импорт добавляет новые записи; существующие ID не перезаписываются. Профили и история проверяются совместно: история может ссылаться на профиль из того же импорта. Дубликаты, неизвестные ссылки и неверные значения отклоняются; при ошибке сохраняется исходный dataset. Форма не импортирует новые каталоги навыков/событий.

Откройте **«Импорт данных»** в демонстрационном меню. Можно загрузить один файл или оба одновременно. UI принимает объект `{"employees": [...]}`; массив профилей также оборачивается в стартовый формат перед передачей core. После импорта новый сотрудник автоматически выбран в списке — перейдите в режим «Сотрудник». Работает тот же движок.

Кнопка **«Скачать пример профиля»** создаёт полный профиль из кита с новым ID `JURY_001`. Можно также скопировать профиль из employees.json, изменить employee_id/full_name и сохранить валидные ссылки. Повторный импорт того же ID отклоняется. Файлы сохраняются во временный каталог только на время вызова core и затем удаляются. Подробности схемы: [README стартового кита](case/case_1/career_quest_dataset/README.ru.md).

## Показ жюри: 60–90 секунд

1. 0–15 с: выбрать E0002 / Arman Zhaksylykov; показать Middle → Senior, стаж, разрывы.
2. 15–35 с: открыть «Карта развития», выбрать разрыв API Design и рекомендованный System Design Fundamentals. Показать текущий уровень, прогноз и требование Senior.
3. 35–50 с: нажать «Завершить шаг на карте»; показать изменившиеся узлы, статус завершения, рост прогресса и новую рекомендацию в списке шагов.
4. 50–65 с: открыть HR: разрывы, сотрудники без шага, участие/завершения.
5. 65–90 с: импортировать дополнительный профиль/историю, выбрать нового сотрудника и показать рекомендации того же движка.

## Карта развития

Отдельная вкладка на экране сотрудника показывает до пяти навыков цели. В первую очередь видны навыки выбранной рекомендации и разрывы; выбор любого навыка в списке добавляет его на схему. Флажок раскрывает остальные навыки профиля грейда, а не весь каталог из 60 навыков. Списки «Навык на карте» и «Шаг на карте» синхронизированы со схемой; графические узлы сами по себе не являются кнопками.

Ветки сгруппированы по фактическим `category` и `type` из `skills.json`; русские подписи — перевод категорий. Порядок и размещение узлов служат только визуальной группировкой. Сплошная линия означает связь активности с навыком из `develops_skills`, пунктир — условие допуска из `prerequisites`. Связей зависимости между навыками и выдуманной лестницы обязательных событий нет.

Выбранный путь показывает текущий уровень → активность → ожидаемый уровень и требование грейда. Текущие уровни, требования и прогноз `skill_changes` поступают из `core/api.py`. Значения `gain` и `max_level` — подписи исходного каталога; UI не рассчитывает и не начисляет прирост. Если движок не вернул прирост для навыка, карта не придумывает прогноз. Активности вне рекомендаций перечислены как каталог, без обещания допуска. Карточка выбранного навыка объясняет его связь с требованиями роли и показывает описание из кита.

Завершение использует тот же адаптер, что основной маршрут, и повторно запрашивает профиль из core. Карта сохраняет фактические уровни до/после последнего завершённого шага в текущей сессии; можно выбрать следующий рекомендованный шаг. После импорта снимок завершения сбрасывается, чтобы не показывать устаревший результат. Состояния различаются текстом и цветом: «есть разрыв», «освоено», «рекомендовано», «активность завершена». «Освоено» означает выполнение требования выбранного грейда, а не обязательно уровень 5. Для Lead нового грейда нет: отображаются требования текущего профиля.

Карта покрыта проверками реального движка, импортированного профиля, ограничения `max_level`, источников линий, пустых рекомендаций, длинных подписей и сохранения выбора после завершения. Эти проверки находятся в `ui/checks/test_development_map.py`; основной алгоритм `core/` не изменён.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s ui/checks -p "test_*.py" -v
```

Для этих проверок используйте `CAREER_QUEST_AI_PROVIDER=none`; тесты AI сами подставляют mock. Проверены все 200 профилей, допустимость кандидатов, gain/max_level, даты оценки, изменение прогресса/HR, импорт новых профилей и истории, откат ошибок, отсутствие повторного начисления и AI-fallback. Streamlit AppTest проходит профиль → завершение → HR → новый профиль → завершение; проверяет понятную ошибку пустой загрузки. Дополнительно проверяются реальные поля core, отсутствие тихой подмены на демо и отображение таймаута AI в UI. Тесты API не доказывают доступность живого сервиса.

Браузерная приёмка на запущенном сервере:

```bash
python -m pip install playwright==1.63.0
python -m playwright install chromium
python -m ui.checks.browser_check --url http://localhost:8501
python -m ui.checks.theme_check --url http://localhost:8501
```

Проверка темы измеряет контраст текста на экранах сотрудника, HR и импорта: системные светлая/тёмная темы и сохранённая противоположная тема. У проверяемого текста контраст не ниже 4,5:1; основная кнопка остаётся видимой на 1366×768.

| Сценарий | Результат после интеграции |
|---|---|
| Профиль и выбор произвольного сотрудника | Пройдено, настоящий датасет core |
| Рекомендации, факторы, ожидаемый прирост | Пройдено, порядок и значения из core |
| Завершение и пересчёт | Пройдено, E0001: 54,5% → 60,6%; изменяются навыки и следующий шаг |
| Сохранение при переключении экранов | Пройдено в Streamlit и браузере |
| HR: разрывы, поддержка, участие | Пройдено; число участий обозначает записи истории, не уникальных людей |
| Новый профиль и история | Пройдено; импортированный сотрудник получает рекомендации того же core |
| Неверный JSON | Понятная ошибка, прежний датасет сохраняется |
| Ноутбук 1366×768 и длинные названия | Пройдено; основная кнопка целиком в первом экране, длинный текст переносится |

Браузерный сценарий сохраняет скриншоты и результаты во временную папку, указанную в выводе. Визуальный стиль проверен относительно [Halyk Bank](https://halykbank.kz/): светлый фон, зелёные акценты и карточки внутреннего продукта.

## Ограничения

Переключатель «Сотрудник / HR» — только демонстрационные представления, не разграничение доступа. Нет авторизации, постоянной БД и аудита: изменения живут в сессии и сбрасываются в новом сеансе или при перезапуске сервера. Только синтетические данные; публичных рейтингов нет. Интерфейс русский, названия каталога английские. Траектория детерминированно следует следующему грейду текущей роли; цель другой роли учитывается только LLM при выборе близких кандидатов. Для Lead показываются требования поддержания Lead. Повышение грейда автоматически не выполняется; проценты означают покрытие требований по навыкам, а не вероятность повышения.

История содержит дату сессии, не отдельную дату завершения; для пересчёта используется date. Кнопка завершения симулирует выполнение в дату среза, в том числе для будущих сессий. Семантическая дедупликация разных record_id одной сессии не реализована. Эвристические веса не обучены и не откалиброваны на скрытых профилях жюри. Live API и качество LLM требуют отдельной проверки с ключами команды.
