# Career Quest · HackAlem AI / Halyk Bank

Карьерный навигатор: профиль → разрывы до следующего грейда → объяснимый следующий шаг → завершение → обновлённый прогресс. HR видит частые разрывы, сотрудников без шага и участие по событиям.

**Основной сценарий работает на стартовом ките** из `case/case_1/career_quest_dataset`: 200 сотрудников, 40 событий, 60 навыков, 2 743 записи истории. Дата среза — 2026-10-01. Временные демопрофили не используются при обычном запуске. Дополнительный синтетический профиль проверен в фактическом формате кита; скрытых профилей жюри у нас нет.

## Установка и запуск

Python 3.11+ (проверено на Python 3.14 / Windows). Из корня проекта:

```bash
python -m pip install -r requirements.txt
```

Одна команда запуска:

```bash
python -m streamlit run app.py --theme.base light --theme.primaryColor "#087f5b"
```

Открыть http://localhost:8501. Без ключей всё работает на детерминированном ранжировании. Папка данных задаётся через CAREER_QUEST_DATA_DIR или боковую панель; изменение применяется кнопкой «Перезагрузить данные».

## Архитектура и AI

`Streamlit → ui/adapter.py → core/api.py → core/engine.py → core/ai.py (опционально)`.

Детерминированный слой считает требования и разрывы следующего грейда текущей роли, воспроизводит завершения после last_review_date по gain/max_level, фильтрует обязательные/неподходящие/недоступные события и проверяет prerequisites. Ранжирование учитывает критичные навыки, историю пропусков и отказов, начатые активности, формат работы и трудозатраты. Формула в CORE_NOTES.md.

LLM выбирает один шаг из максимум трёх близких лидеров (разница ≤ max(1 балл, 10% оценки лидера)) и упорядочивает существующие фактические объяснения. Модель не генерирует новые факты и не меняет score, требования, навыки, gain/max_level или прогресс. Ответ с неизвестным событием или индексом причины отклоняется. Интерфейс показывает AI/fallback.

Реализованы OpenAI Responses со Structured Outputs и NVIDIA NIM Chat Completions. **Живой вызов API не проверен: в рабочем окружении нет ключей.** Успех, ошибки, таймаут и некорректные ответы проверены через mock. Документация: [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [NVIDIA](https://docs.api.nvidia.com/nim/re/reference/llm-apis).

### Переменные окружения

| Переменная | Значение |
|---|---|
| CAREER_QUEST_AI_PROVIDER | none (по умолчанию), openai, nvidia |
| CAREER_QUEST_AI_MODEL | ID модели, доступной вашей команде; обязательно для API |
| OPENAI_API_KEY | Секрет OpenAI, только в окружении |
| NVIDIA_API_KEY | Секрет NVIDIA, только в окружении |
| CAREER_QUEST_AI_TIMEOUT | 8 секунд по умолчанию, ограничение 0.1–9 секунд |

Задайте переменные до запуска. Не помещайте ключи в код или Git. `.env` автоматически не загружается. Жёсткое ограничение ожидания выполняется фоновым потоком; повторов нет. После ошибки одинаковые факты 30 секунд используют fallback. До 128 успешных ответов кешируются, одновременно допускаются два HTTP-запроса. HR не вызывает API для каждого профиля. Имя, employee_id и исходная история в API не отправляются; передаются роль/грейд/цель/формат работы и факты кандидатов.

## Входные данные

Схема прочитана в README.ru.md стартового кита:

- employees.json: объект с массивом employees; meta необязателен для дополнительного файла. Профиль: employee_id, full_name, department, role, grade, manager_id, hire_date, tenure_months, work_format, preferred_language, career_goal, skills, last_review_date. skills — skill_id → целое 0–5, отсутствующий навык считается 0.
- skills.json: meta.as_of_date, skills[], role_profiles[] с required_skills и critical_skills.
- events.json: events[], включая develops_skills (skill_id/gain/max_level), prerequisites, mandatory, аудиторию и upcoming_sessions.
- activity_history.csv: `record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by`.

Статусы: completed, in_progress, dropped, no_show, declined, overdue. UTF-8, до 10 МБ на файл. Импорт добавляет новые записи; существующие ID не перезаписываются. Профили и история проверяются совместно: история может ссылаться на профиль из того же импорта. Дубликаты, неизвестные ссылки и неверные значения отклоняются; при ошибке сохраняется исходный dataset. Форма не импортирует новые каталоги навыков/событий.

Для проверки скопируйте профиль из employees.json, задайте новый employee_id и full_name, сохраните валидные ссылки и оберните в `{"employees": [...]}`. После импорта выберите его в общем списке: работает тот же движок.

## Показ жюри: 60–90 секунд

1. 0–15 с: выбрать E0002 / Arman Zhaksylykov; показать Middle → Senior, стаж, разрывы.
2. 15–35 с: показать лучший шаг, критичные навыки, историю и ожидаемый прирост.
3. 35–50 с: завершить шаг; показать рост прогресса, историю и новые рекомендации.
4. 50–65 с: открыть HR: разрывы, сотрудники без шага, участие/завершения.
5. 65–90 с: импортировать дополнительный профиль/историю, выбрать нового сотрудника и показать рекомендации того же движка.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Проверены все 200 профилей, допустимость кандидатов, gain/max_level, даты оценки, изменение прогресса/HR, импорт новых профилей и истории, откат ошибок, отсутствие повторного начисления и AI-fallback. Streamlit AppTest проходит профиль → завершение → HR → новый профиль → завершение; проверяет понятную ошибку пустой загрузки. Проверки API используют mock, не живой сервис.

## Ограничения

Переключатель «Сотрудник / HR» — только демонстрационные представления, не разграничение доступа. Нет авторизации, постоянной БД и аудита: изменения живут в сессии и сбрасываются при перезагрузке. Только синтетические данные; публичных рейтингов нет. Интерфейс русский, названия каталога английские. Траектория детерминированно следует следующему грейду текущей роли; цель другой роли учитывается только LLM при выборе близких кандидатов. Для Lead показываются требования поддержания Lead. Повышение грейда автоматически не выполняется.

История содержит дату сессии, не отдельную дату завершения; для пересчёта используется date. Кнопка завершения симулирует выполнение в дату среза, в том числе для будущих сессий. Семантическая дедупликация разных record_id одной сессии не реализована. Эвристические веса не обучены и не откалиброваны на скрытых профилях жюри. Live API и качество LLM требуют отдельной проверки с ключами команды.
